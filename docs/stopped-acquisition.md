# RAM Stop versus file-triage Stop

**RAM acquisition:** Stop preserves captured memory at its already selected destination without another prompt. Physical acquisitions save a ZIP named `<existing-prefix>-RAM.zip`, containing the unchanged `<existing-prefix>-RAM.lime`, `acquisition.json`, and `backend.log`. Stopped acquisitions also include the partial-image JSON sidecar recording captured ranges and unverified/incomplete coverage. Both the image and ZIP have SHA-256 hashes; images are verified after packaging. ZIP64 supports large RAM images. Packaging uses uncompressed entries and temporarily needs space for both the image and ZIP at the selected destination. If packaging fails, captured files remain in the recovery directory identified in the error. Truncated LiME data may require recovery before import. Unprivileged acquisition finalizes a readable ZIP with each captured region's bytes, hash, segment/address map, unreadable bytes and bytes not attempted after Stop. Final hashing/publication completes before the RAM page offers Finish. Existing files are not overwritten; stopping before any bytes are acquired creates no empty evidence image.

**File triage:** Stop preserves completed findings and diagnostics in RAM and offers Resume, Back and Next. It does not automatically write a ZIP, even when RAM was acquired earlier. Next opens the export stage, where the examiner can select a destination and click Export ZIP to save the stopped findings. Finish on a stopped scan closes without saving its file-triage results. Already saved RAM is unaffected and is not duplicated in file-triage ZIPs.

**Resume:** available during the same running TERRA session. It retains the same evidence store, targets, configuration and counts. Directory traversal restarts, skipping paths whose file processing completed and parser companions already collected. An interrupted file is retried. Existing category contents remain visible and no duplicate folder-name findings are added. Live categories already acquired are retained; live stages that did not complete may be retried. The resume event and count are recorded in diagnostics/summary. Resume does not reacquire RAM. Completed paths are not reread to discover later changes: this is continuation of a triage collection, not continuous monitoring or an atomic filesystem snapshot. New source paths encountered during resumed traversal can be collected. No resume checkpoint is written to disk; closing TERRA ends in-memory resumability.

Completed case triage keeps the existing cases-folder default, with the option to select another destination. Finish saves an unsaved completed case. Stopped cases have an optional export instead. See [case exports and imports](case-export-import.md).

Relevant modules: RAM collectors preserve interrupted memory; `controllers/scan_controller.py` manages file checkpoints and resumed workers; `interface/pages/analysis.py` exposes Resume; `interface/main_window.py` routes optional exports. Tests cover stopped/RAM preservation, interrupted-file retry, skipped completed reads, retained GUI results, stopped-case Finish without export and destination selection.
